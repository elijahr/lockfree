## Phase 3.4 investigation — pop-clears mechanism (CRITICAL-2 disposition)

The Phase 3.2 impl-plan review surfaced CRITICAL-2: "pop-clears defect premise contradicted by source." Phase 3.4 investigation resolves this as follows:

**Source-of-truth verification** (`grep -n "let value" src/lockfree/typestates/*_pop.nim` in `/Users/eek/Development/lockfreequeues`):

- v5.0.0 `lockfreequeues` source-of-truth: ALL 8 pop sites use **plain reads** (e.g., `let value = queue.storage[op.slot]`). The design §4.5.2 table is **correct** for the v5.0.0 baseline being lifted.
- `/Users/eek/Development/lockfree` integration target: 4 bounded pop sites at `src/lockfree/typestates/{spsc,mpsc,spmc,mpmc}_pop.nim` already wrap the read in `move(...)` as a partial integration step. The 4 unbounded pop sites live inline in `src/lockfree/queue.nim` (lines 874, 1360, 1380, 1475) and likewise already use `move(seg.data[...])`.

**`move()` vs `.reset()` for ManagedRef/Slice (`distinct uint`)**:

The design §4.5.3 mechanism family (1) recommends `.reset()` after the read. Phase 3.4 investigation confirms that `move()` is **observationally equivalent** to `.reset()` for the slot-clearing purpose under all relevant T:

- POD T: both leave the slot's bits at 0 (default).
- `ref T` / `string` / `seq[T]`: `move()` runs `=sink`, leaving the source in the moved-from sentinel (nil ref, empty string/seq). `reset()` writes the same default.
- `ManagedRef[X] = distinct uint` / `ManagedSlice[T] = distinct uint`: neither has a `=destroy` hook (the lifecycle is in the wrappers per §4.5.3 — caller-side `ref X` going out of scope runs the dec). Both `move(slot)` and `slot.reset()` leave the bits at 0. The destructor walk (§4.7) reads the slot bits and decides via `seqIsLive(slot)`; a 0-bit slot returns false from any reasonable predicate and is skipped.

**Destructor-walk path verification**:

- `imports/nim-debra/src/debra/typestates/retire.nim`: nebr retires a raw `(pointer, destructor)` pair into a limbo bag (line 109 onward). No slot walk; the destructor closure is the only reclamation hook.
- `src/lockfree/queue.nim:538` (`segmentDestructor`): walks every slot 0..S-1 and calls `reset(seg.data[i])` for non-POD T. This is safe both for unpopped slots (the `reset` runs the proper destructor) and for popped slots (after `move()` the slot is default-valued; `reset()` is a no-op or runs `=destroy(default(T))` which is idempotent).

**Verdict**: `move()` is sufficient for ManagedRef/Slice. The slot-clearing semantics match design §4.5.3 family (1). The lockfree integration target already has the correct `move()` at every site.

**Plan disposition**:

- The 8 `T-INTEGRATE-POP.*` tasks are renamed `T-VERIFY-POP-CLEARS.*` and scoped to **regression tests only** (the code change is already in the lockfree tree via the prior integration substrate that wrapped each read in `move()`).
- Path cites in those tasks are corrected to the verified working-tree paths: bounded → `src/lockfree/typestates/{spsc,mpsc,spmc,mpmc}_pop.nim`; unbounded → `src/lockfree/queue.nim` (specific line numbers below).
- §4.5.2 design table and the safety-argument's pop-clears claims are updated to acknowledge the v5.0.0 lifted code uses `move()` at each site, and that `move()` is equivalent to the §4.5.3 family (1) `.reset()` mechanism for slot-clearing.
- §7.9 in/out table entry "fix payload-clear across all 8 arms" is reframed as "verify payload-clear semantics + add per-arm regression tests" (the code-edit deliverable is closed via prior integration substrate).
- R2 (pop-clears 8-arm) risk is retained because the **regression-test** deliverable is still in scope — without per-MM tests, a future refactor could silently regress the clear discipline.

### PG-5 race protocol (Phase 3.4 CRITICAL-3 fix)

Phase 3.2 review flagged that PG-5 originally ran T-MANAGED-REF + T-MANAGED-SLICE + T-NIMONY-ARMS in parallel against the same managed_*.nim files, with the orchestrator told to "serialize OR coordinate via a merge dispatch" but no protocol written. Phase 3.4 resolves this via **Option A: hard serialization with stub protocol**.

**Updated 2026-06-06 (Wave A/E)**: T-MANAGED-SLICE was briefly obsoleted then REINSTATED as the v3 box-pattern (`distinct uint` box pointer to heap StringBox/SeqBox; library-managed alloc/dealloc). The PG-5 race protocol applies to `managed_ref.nim`; `managed_slice.nim`'s per-MM `when` arms share a uniform body (no nimony-specific arm needed — Cell 14 validates), so there is no PG-5a/PG-5b race on managed_slice.nim. The string/seq Path-C arm at the cell-array layer is selected via `SlotEncoding[T]` per Wave C (no inline queue.nim string/seq sub-branch needed). PG-5a now runs T-MANAGED-REF + T-MANAGED-SLICE in parallel.

**Protocol**:

1. **PG-5a** runs T-MANAGED-REF + T-MANAGED-SLICE (REINSTATED v3 box-pattern 2026-06-06). T-MANAGED-REF creates `managed_ref.nim` with shim arms for arc / orc / atomicArc / refc / none AND emits a stub nimony arm at the documented insertion point:

   ```nim
   when defined(nimony):
     {.error: "filled by T-NIMONY-ARMS".}
   ```

   The stub MUST be placed at the canonical insertion point per design §4.3.5 (managed_ref) — immediately after the `none` arm, before any per-shim helper procs. (Note: §4.4.5 insertion-point text has been rewritten; the string/seq Path-C nimony sub-branch now lives inline in queue.nim, not in a separate managed_slice.nim — that module was deleted 2026-06-06.) A precise grep target for T-NIMONY-ARMS:

   ```bash
   grep -n 'filled by T-NIMONY-ARMS' src/lockfree/managed_ref.nim
   ```

   Each grep MUST return exactly one hit per file.

2. **PG-5b** runs T-NIMONY-ARMS only (single-task PG). T-NIMONY-ARMS:
   - Adds real nimony arms to `src/lockfree/atomics.nim`, `src/lockfree/atomics/dsl.nim`, `src/lockfree/smr/nebr/manager.nim` (no overlap with PG-5a files).
   - Replaces the stub block in `managed_ref.nim` with real impl (the `{.error.}` line is deleted; the `when defined(nimony):` branch wraps the new code). (Updated 2026-06-06: managed_slice.nim no longer exists; the string/seq nimony sub-branch lives inline in queue.nim and is amended here too.)

3. **Conflict-free invariant**: Because the `when defined(nimony):` branch is the ONLY shared edit surface in `managed_ref.nim` and PG-5a deliberately stubs it with a known-grep-able sentinel for PG-5b to fill, there is no race possible on that file. The orchestrator does NOT need a merge dispatch. For queue.nim, T-PATH-C-DISPATCH (PG-6, after PG-5b) writes the non-nimony string/seq Path-C branches, and the nimony sub-branch is added by T-NIMONY-ARMS (PG-5b) — these are non-overlapping edits because T-NIMONY-ARMS runs before T-PATH-C-DISPATCH (the dependency order is preserved).

4. **Verification**: After PG-5b completes, `grep -rn 'filled by T-NIMONY-ARMS' src/` MUST return zero hits. This is added to T-NIMONY-ARMS's acceptance.

### T-DESTRUCTOR-WALK — Implement `=destroy` walk for ref-typed payloads

- `drain(q)` — explicit; iterator that yields remaining items; leaves queue empty but does not run `=destroy`-equivalent decref (the yielded values' caller-side `=destroy` accounts for refs).
