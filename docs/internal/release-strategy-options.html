Phase 1.5 Q7 / Handoff Q14 decision aid — interactive

2026-06-05

We are renaming lockfreequeues to lockfree. The renamed repository inherits every release tag the old project ever published — v4.0.0, v4.1.0, v5.0.0 — even though the nimble package name itself is changing. Two questions need answers before we cut the first release of the umbrella: what version number do we tag first, and what do we do with the inherited tags. Pick options on the right; explanations highlight here in sync.

The two axes

Axis 1 — Starting version number

The first tag we cut on elijahr/lockfree signals a promise. v0.x says "still settling — expect breaks." v1.0.0 says "this surface is stable, breaking changes will bump to v2." Continuing the old v5.x line is technically possible but misleading because the nimble package name changed underneath.

Axis 2 — Inherited tag handling

The renamed repo's tag list currently shows the lockfreequeues history. Left alone, the GitHub Releases page mixes pre-rename and post-rename tags in confusing order. We can keep them, delete them, or preserve them on an archive repo while cleaning the active one.

The four tag-handling options

A

Keep all old tags

Do nothing. The renamed repo's tag list shows v0.1.0 alongside v4.0.0, v4.1.0, v5.0.0.

What changes on GitHub

  • Repo renamed; everything else untouched
  • Tag list mixes eras in non-chronological order
  • Releases page lists old lockfreequeues releases as if they were lockfree releases
  • No git surgery, no destructive ops

What changes for users

  • Tag-pinned installs of old lockfreequeues tags keep working from the renamed URL
  • Browsing the repo is jarring — old tags look current
  • Changelog continuity is preserved (lossless)
Operational cost: Trivial Reversibility: Easy
B

Delete old tags + redirect-stub

Delete v4.x and v5.x tags from the renamed repo. Publish one final lockfreequeues v5.0.1 to nimble whose package metadata says "use lockfree instead."

What changes on GitHub

  • Tag list is clean — only v0.x onward
  • Old release artifacts on GitHub Releases are gone
  • Destructive op on the renamed repo (no backup)
  • One last nimble publish for the deprecation pointer

What changes for users

  • Tag-pinned lockfreequeues == v5.0.0 resolution breaks at the source URL
  • Nimble users see a clean deprecation hop on next install
  • Historical tarballs disappear from the canonical location
Operational cost: Moderate Reversibility: Difficult
C

Archive history, clean active Recommended

Before renaming, clone the full lockfreequeues history. Rename, then delete v4.x/v5.x tags from the renamed repo. Push the pre-rename clone (all tags intact) to a fresh lockfreequeues archive repo.

What changes on GitHub

  • Active lockfree repo has a clean tag list (v0.x only)
  • New lockfreequeues archive repo holds the full pre-rename history
  • Archive repo gets a deprecation README pointing at lockfree
  • Requires careful sequencing (clone before delete)

What changes for users

  • Tag-pinned old installs resolve from the archive URL after one redirect
  • Active repo's tag list is honest about what's current
  • Full history remains discoverable and citable
Operational cost: Moderate Reversibility: Easy
D

Tag v1.0.0, leave history

No surgery. Tag v1.0.0 of the new umbrella on top of inherited history. Old tags stay; new tag follows v5.0.0 in raw git but lives in a different nimble package.

What changes on GitHub

  • Tag list shows v1.0.0 next to v5.0.0 — eyebrow-raising
  • No destructive ops, no archive repo
  • Git history is fully linear and intact
  • Releases page reads strangely without context

What changes for users

  • Old tag-pinned installs continue to resolve
  • Semver narrative requires a README explainer
  • Stable-promise claim is made on top of unproven new APIs
Operational cost: Trivial Reversibility: Easy

Version number choices

v0.1.0 Recommended

Signals "umbrella is new, surface still settling, expect breaking changes before 1.0." Honest about a first integrated release that wraps ManagedRef, ManagedSlice, and the nimony port.

Honesty: High

v1.0.0

Signals "stable promise, well-considered surface, breaking changes bump to v2." Strong claim to make on a first integrated cut of brand-new submodules.

Honesty: Tension

v5.1.0

Continues lockfreequeues semver. But the nimble package name changed, so tooling sees this as the first release of a completely new package called lockfree starting at a strange version.

Honesty: Misleading

Cross-cutting sub-questions

Archive: manual push of pre-rename clone Recommended

Create a fresh empty lockfreequeues repo on GitHub, then push the pre-rename clone (all tags, all branches) into it manually. Cleaner provenance, no false fork signal, accurate network graphs.

Archive: fresh-empty (no history push)

Create the archive repo as a fresh empty repository with only a deprecation README. No tag history mirrored. Simpler but loses the discoverability of historical tags at the archive URL — tag-pinned downstreams cannot resolve.

Publish lockfreequeues v5.0.1 redirect-stub Recommended

Existing requires "lockfreequeues == ..." users will eventually nimble refresh. A final lockfreequeues v5.0.1 publish whose description and README point at lockfree turns a silent dead end into a graceful hop. Cost is low; goodwill for pinned downstream consumers is meaningful.

Skip the redirect-stub

Do not publish a final lockfreequeues stub. Pinned downstream users discover the rename by error on their next nimble refresh. Saves one nimble publish step but trades operator effort for downstream confusion.

What you're picking

If you stay on the recommended path (C + v0.1.0 + manual-push-history + redirect-stub):
  • Clone lockfreequeues (all tags, all branches) to a working directory before renaming
  • Rename elijahr/lockfreequeues to elijahr/lockfree on GitHub
  • Delete v4.0.0, v4.1.0, v5.0.0 tags from the renamed repo (local + remote)
  • Create a fresh empty elijahr/lockfreequeues archive repo on GitHub
  • Push the pre-rename clone (with all tags) to the archive repo
  • Add a deprecation README to the archive pointing at elijahr/lockfree
  • Tag v0.1.0 on elijahr/lockfree when the umbrella is ready to ship
  • Publish final lockfreequeues v5.0.1 redirect-stub to nimble with deprecation metadata
